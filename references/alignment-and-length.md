# 开稿对齐与字数锁定协议

> 这是所有“要产出成稿”的入口前置门禁。探索灵感可以先发散，但一旦进入 shape / write / rewrite，必须先完成本协议。

## 1. 对齐原则

开头不是让模型展示思考过程，而是让用户看见**可确认的工作契约**。只陈述结论、假设和待确认项，不暴露内部推理链。

第一次进入写作任务时，先汇总用户已经给出的信息；已经明确的内容不要重复追问。对尚未明确、且会实质改变成稿的项目，用一张简短《开稿对齐卡》确认。

必须覆盖：

- **写作目标**：这篇文章最终要让读者知道、相信、感受或采取什么行动。
- **目标读者**：谁会读，读者已有多少背景知识。
- **体裁与载体**：特稿、调查、回忆录、商业长文、公众号、X、小红书等。
- **核心命题**：一句话说清文章真正要回答的问题。
- **事实边界**：只允许使用哪些材料；哪些可以确定性推导；哪些必须标记未知。非虚构任务同时锁定 `source_policy / reconstruction_policy / unknown_policy` 并读取 [nonfiction-fidelity.md](nonfiction-fidelity.md)。默认是 `closed_corpus + reconstruction forbidden + unknown omit`；关键缺口阻塞任务时才升级为 `ask_if_blocking`。
- **叙事人称 / POV**：正文用第一人称、第三人称或其他视角；标题包装必须服从同一 POV，除非明确标注为另一种版本。
- **原话处理**：逐字保留、轻度整理或允许转述；未授权时默认逐字保真。
- **风格**：指定 style ID、作者 DNA，或明确使用默认风格。
- **交付形式**：正文、标题、摘要、脚注、引用、社交版是否包含。
- **字数锁定**：目标字数、允许区间、`count_mode` 与 `count_scope`。默认口径来自 [`../runtime-contract.json`](../runtime-contract.json)：中文 `zh_units`，英文 `words`；默认范围是正文 `body`。若平台自带计数器且用户以平台限制为准，则锁定为 `platform`。标题、脚注、包装文案是否计入必须在开稿时确定，不能终审再换口径。
- **循环预算**：默认值读取 runtime contract。用户可用 `--loops N` 全局覆盖，或用 `--shape-loops / --draft-loops / --review-loops / --package-loops` 分阶段覆盖。具体语义见 [loop-policy.md](loop-policy.md)。
- **交互模式**：默认 `auto`，对齐后自动完成后续阶段；用户想查看中间版本时可选 `checkpoint`，并指定 shape / draft / review。checkpoint 只是用户反馈节点，不增加 reviewer。
- **必须保留 / 必须避开**：用户特别在意的事实、观点、语气和禁区。

用户若已经一次性提供完整约束，直接回显对齐卡并进入下一步，不要为了仪式感再问一遍。

## 2. 字数锁定

字数必须在正文写作前成为硬约束，不能写完后才说“差不多”。

### 用户给精确字数

例如“写 3000 字”，先锁计数口径，再锁数值：

- `target = 3000`
- `count_mode = zh_units`（若用户说“按公众号后台字数”，则改为 `platform`）
- 默认验收带由 runtime contract 的容差生成；当前默认是 ±5%，即 `2850–3150`
- 若用户明确给出上下限，以用户区间覆盖默认验收带。

### 用户给范围

例如“3000–4000 字”：

- `acceptance_band = 3000–4000`
- 选定一个单一工作目标 `target`，默认取区间中点 3500。
- 全流程沿用同一个 `count_mode`；不能 Shape 用汉字数、终审又改成含标点字符数。
- 节拍、段落预算和最终验收围绕 `target` 设计，但最终只要落入用户区间即可。

### 用户没有给字数

不能静默无限写。根据体裁和载体提出**一个具体目标字数 + 验收带**，放入对齐卡让用户确认。

若用户明确说“你定”“直接写，不用问”，视为授权：模型自行给出目标和验收带，回显后立即执行。

## 3. 字数预算

进入 shape 前，把总目标拆成内容预算，而不是套统一的 15/70/15：

- 每个主要段落 / 场景必须有预计字数。
- 所有预算相加应落在 `target` 的结构预算容差内；当前默认值由 runtime contract 定义为 ±3%。
- 风格文件可以定义开头、中段、结尾的比例；没有定义时按内容需要分配。
- 写作过程中只在结构节点检查一次偏差，避免每段都机械凑字。
- 若中途发现素材不足以支撑锁定字数，不得用套话注水；应告诉用户缺口，或在用户已授权自行处理时缩减目标并明确变更。

## 4. 变更控制

锁定后，以下变化必须重新对齐，并递增 `alignment_revision`，不能静默覆盖旧契约：

- 总字数变化超过 10%；
- 体裁或平台变化；
- 目标读者变化；
- 核心命题变化；
- 事实来源边界变化；
- 风格切换导致结构明显变化。

小幅措辞、段落顺序和局部节拍调整不需要递增 alignment revision；它们进入普通 Feedback Loop。

## 5. 开稿对齐卡

使用 [templates/alignment-card.md](../templates/alignment-card.md)。对齐卡要短，重点是让用户能一眼发现理解偏差。
