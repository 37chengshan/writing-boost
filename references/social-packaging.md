# 社交媒体多端分发与内容包装规范

> 包装可以改变长度和切入点，不能偷换叙事人称、事实或原话。

## 一、包装前先锁 POV

读取《开稿对齐卡》：

- 正文是第三人称特写，默认标题也使用第三人称。
- 正文是第一人称自述，标题才可以直接使用“我”。
- 如果要同时提供不同 POV 的标题，必须显式标记：
  - **第三人称特写版**
  - **第一人称专栏 / 自述版**
- 不得为了点击率把第三人称报道擅自包装成“我”，让读者误以为正文由当事人亲述。

## 二、转译原则

1. **单点爆破**：每个短版只提炼一个冲突或场景，不强行概括全文。
2. **事实不升级**：标题中的身份、数字、引语都必须来自正文事实账本。
3. **原话不改造**：带引号的标题只使用真实 Quote ID 或明确说明为概括性标题。
4. **物象优先**：可优先使用正文已经完成闭环的物象，不新造“更抓眼球”的细节。
5. **平台适配不改变人格**：平台语气可以更短、更快，但不能把人物说话方式重新营销化。

## 三、平台矩阵

| 平台 | 形式 | 常见长度 | 包装重点 |
| :--- | :--- | :--- | :--- |
| X | 单帖 / Thread | 平台限制内 | 单一事实冲突 + 来源明确的视觉锚点 |
| 小红书 | 图文 / 长文 | 按平台需求 | 生活化入口，但不虚构第一人称体验 |
| 公众号 | 微特稿 / 长文 | 按开稿字数锁 | 保留正文 POV 与核心证据链 |

## 四、包装反馈 Loop

包装默认先出一版，不强制双循环。用户认为标题、摘要或平台语气不合适时，按照 [loop-policy.md](loop-policy.md) 只循环 Packaging，不回头重写正文；除非反馈实际改变了正文 POV、事实或核心命题。
